## New findings

- **P1-A: the unit probably blocks bwrap** (`compile-api.service:90-91`,
  inferred). `~@privileged` removes `pivot_root`, `chroot`, `capset`,
  `setuid`/`setgroups` again after `@mount` allows them. Fails closed (startup
  probe refuses to start), so it blocks the deploy rather than opening a hole.
- **P1-B: unsandboxed is still possible behind a proxy** (`config.rs:468-490`,
  `build_sandbox.rs:70`). Default mode is `none`; loopback bind with tokens set
  and `PNC_TRUST_PROXY` unset passes validation on Linux. Fix: refuse `none`
  whenever auth tokens are set, or default to `bwrap` on Linux.
- **P1-C: abandoned module compiles pile up** (`wasm_runner.rs:328-344`,
  inferred). The build slot is released while a timed-out Cranelift compile
  keeps running in the server; one IP within 20/min can fill the CPU quota and
  drive the server into OOM and the start limit. Fix: move the build-slot
  permit into the compile helper thread.
- **P1-D: `verify-sandbox.sh` can pass with a broken sandbox.** The env-file
  probes fail anyway (file is `600 root`), and every probe passes on any
  `"ok":false`, including a deny-list or 4xx/5xx. Fix: require rustc's
  "couldn't read ... No such file" text per probe, plus a positive control and
  a check that the deny-list is really off for the test.
- **Systemd loosening (inferred):** dropping `ProtectKernelTunables` and
  `ProtectKernelLogs` is required; `ProtectProc`/`ProcSubset` is unproven
  (re-enable each and see if the probe passes). The server itself gains user
  namespaces, mount syscalls, netlink and process visibility. Net: the
  file-read class is much safer; after a wasmtime escape the host is less
  safe. Fix: a separate builder unit without the env file that holds the
  loosened settings and also runs the wasm; server unit back to
  `RestrictNamespaces=yes`.

## P2

- Deny-list bypasses (sandbox `none` only): `#$x` macro-forwarded attributes
  (`source_policy.rs:138-147`); `mod $n;` (`:131-136`); `is_alphabetic` vs
  rustc identifier rules (`:194-200`, unverified). Fix: reject non-ASCII
  outside comments/strings and `#` followed by `$`.
- No request or body-read timeout (`middleware.rs:283`, `lib.rs:359`).
- `/metrics` is public behind a proxy when `TRUST_PROXY` is off
  (`middleware.rs:205`).
- Denied requests still store a /64 entry (`rate_limit.rs:272`).
- `child.wait()` unbounded once pipes close (`proc_tree.rs:170`); slot
  released even with survivors (`:304`).
- Build artifact read follows symlinks (`wasm_builder.rs:424,453`).

## Path to a public deploy

1. Fix the syscall filter or split out a builder unit; confirm on Linux that
   the startup probe passes ("isolation checks passed", "build self-test
   passed").
2. Close P1-B. 3. Close P1-C.
4. Make the verify script require positive evidence, then run it.
5. Operator checks: unprivileged user namespaces allowed (sysctl, AppArmor on
   Ubuntu 24.04+); service refuses to start with sandbox `none` and tokens
   set; `/metrics` returns 403 through the proxy; `cargo audit`.
