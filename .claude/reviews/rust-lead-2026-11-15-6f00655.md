## Verdict

**Ship after 3 fixes.** The game crate is in good shape: `#![forbid(unsafe_code)]`, no
reachable `unwrap`/`expect`/`panic!` in non-test game code, saves are versioned and
recover safely, and offline/refused grades never save a clear. But (1) the only release
pipeline (web -> itch / Tauri) builds the **full** game with no demo gate, (2) a native exe
with no env var can never save a clear, and (3) the evidence for hard rule 3 sits in
`#[ignore]`d tests run against an unpinned rustc. Fix or explicitly decide all three before tagging.

## Blockers (must fix before a release tag)

**B1. The release pipeline ships all 96 missions free, ungated.**
`scripts/web-build.ps1:46` runs `cargo build -p pledge_and_crown --target
wasm32-unknown-unknown --profile $CargoProfile` with no `--features demo`.
`web-package.ps1` zips that build, `itch-push.ps1` publishes it, and the Tauri
wrapper (`mobile/src-tauri/tauri.conf.json:7`, frontendDist `../../web`) ships
the same files. The web build has no `PLEDGE_CONFIG` (`web/index.html:85-101`
is a comment), so it runs in offline mode where stub passes **count**. So an
itch upload is the whole product, free, graded by substring rules. The `demo`
feature is only `cargo check`ed (`ci.ps1:55`). No script builds a demo
artifact. *Fix:* add a `-Features` param to `web-build.ps1` that defaults to
`demo`. Make `web-package.ps1` write the build flavour into the zip name, and
have `itch-push.ps1` refuse a full build unless `-Full` is passed. If the full
game on the web is intended, record that as an owner decision.

**B2. A native build without PLEDGE_API_URL can never save a clear.**
`game/src/plugins/compile_client/config.rs:55,263-266`: the native default
target is `Remote("http://127.0.0.1:7878")`. On a player's machine nothing
listens there, so every compile comes back `ApiOutcome::Offline`.
`outcome.rs:441-451` then gives stub feedback with `persist_clear: false`
("this pass won't be saved"). The player cannot clear `intro_let_binding`, so
the game is soft-locked at mission 1. Tests cover this policy
(`unreachable_server_falls_back_to_stub_without_saving`) and it is right for a
dev box. It is wrong as the default for a shipped binary. *Fix:* make the
localhost default `cfg(debug_assertions)` or `feature = "dev"` only. Release
native builds should default to `option_env!("PLEDGE_API_URL")` baked in at
build time, else `None` (offline, stub canonical, same as the web). This
applies before any native artifact ships: a Steam/itch desktop exe or a
`--release` binary handed to a tester. Same release, smaller item:
`game/src/main.rs` has no `cfg_attr(not(debug_assertions), windows_subsystem
= "windows")`, so a Windows player gets a console window behind the game.
There is also no native packaging script at all (assets dir /
`BEVY_ASSET_ROOT`).

**B3. Hard rule 3 is not proven at this commit.**
Every test that actually runs rustc on an NPC's claim is `#[ignore]`:
`game/tests/mission_text.rs:94,604,1701,1720,1914`. CI never runs them
(`ci.ps1:53`, plain `cargo test --workspace`). They also call bare `rustc`.
`print_rustc_version` (`mission_text.rs:1692`) prints the version but does not
check it. Meanwhile the server refuses any rustc except `PINNED_RUSTC_VERSION
= "1.99.0"` (`compile-api/src/toolchain.rs:22`). Several claims quote wording
that changes between rustc versions: E0080 "evaluation panicked: ", E0015's
`for` loop message, "RefCell already borrowed". Stable has probably moved past
1.99 by now, so a developer's `--ignored` run can pass on a different compiler
than the one players get. That is exactly the P0 that rule 3 describes.
*Fix (minutes):* (a) in `print_rustc_version`, assert that the version equals
`pledge_compile_api::toolchain::PINNED_RUSTC_VERSION` (already a
dev-dependency). (b) Before tagging, run on 1.99.0 (cnc is fine):
`cargo test -p pledge_and_crown --test mission_text --test solutions --
--ignored` and `cargo test -p pledge_compile_api --test expectations_proof --
--ignored`. File the output with the release.

## Should fix before v1.0

1. **A saved position inside a solid traps the player for good.**
   `progress.rs:749-766` restores `SavedPlayerPosition` without validation.
   `prop.rs` `slide_move` rejects every step whose foot overlaps a solid, so a
   player who starts inside one can never move. Wave 15 put a solid 64x64
   Throne Dais on a plaza that used to be walkable. Any later map/prop patch
   will do the same to saves made at that spot, and the only escape is New
   Game (it wipes progress). No v2 save exists outside this branch yet, so no
   player is hurt today. *Fix:* on restore, if the foot AABB overlaps any
   `Solid` or the map bounds, fall back to `PLAYER_SPAWN` and log a warning.
   Add one test.

2. **A late verdict shows in the wrong mission's editor.**
   `compile_client.rs:263` calls `editor.set_result(..)` for every result,
   whatever `editor.encounter_id` now is. Real compiles can take up to 60 s.
   Compile A, close the editor, open B, and A's `[ok]` banner appears on B.
   The clear itself goes to the right mission (A). This misleads the player
   but corrupts nothing. *Fix:* persist the clear as now, but only
   `set_result` when `encounter_id == editor.encounter_id`. Otherwise log at
   info.

3. **CI never tests the demo build.** `ci.ps1:55` only runs `cargo check
   --features demo`. The demo branches of
   `demo_availability_matches_the_feature` and `demo_completion_flag`
   (`mission_text.rs:715,735`) therefore never execute. *Fix:* add a step
   `cargo test -p pledge_and_crown --features demo --test mission_text --test
   registry`. It covers the fast tests only.

4. **No fast test checks that the server's mission ids match the game's.**
   `compile-api/src/expectations.rs:1714` asserts `all().len() == 96` and
   nothing more. A typo'd id there makes that mission an unknown encounter.
   The server then answers `ran_not_checked`, the client shows
   `PassedUnverified(Unknown)`, and the clear still counts, so the behaviour
   check silently disappears. *Fix:* in `game/tests/contract.rs`, assert that
   the id set of `pledge_compile_api::expectations::all()` equals the
   `MissionRegistry` id set, in order.

5. **One villager compiler claim is outside every claim set.**
   `mission.rs:389` (`borrow_mut`, the Forgewright): "without it the compiler
   rejects the assignment (E0308)". I believe the claim is correct (type check
   comes before borrowck), but nothing compiles it.
   `assert_claims_cover_texts` is only run over trial owners and the Act 9/10
   villagers. *Fix:* run it over the texts of every registered mission plus
   all `AUTHORED` rows, with one claims table. Then a newly named code
   anywhere fails CI. Add the `borrow_mut` claim.

6. **Turn hard rule 1 from an observation into enforcement in compile-api and
   tools.** Neither `compile-api/src/lib.rs` nor `compile-api/src/main.rs`
   carries `#![forbid(unsafe_code)]`. `tools/render-refs` and
   `tools/web-serve` don't either. Today all three contain zero `unsafe`
   outside string literals (verified; rustix gives safe wrappers). *Fix:* one
   line per crate root.

7. **Curriculum overclaims (rule 4 / marketing).**
   `design/01-curriculum.md:16` and `pitch/deck.template.html:330` say "every
   concept in the Rust Book through Chapter 20". Nothing teaches modules
   (`mod`/`pub`/`use`, Book ch. 7) or writing tests (`#[test]`/`cargo test`,
   ch. 11): no mission, no tutorial section. These are the two things a
   Rust-teaching product is most often judged on. Either add two missions
   (Act 3 and Act 5 fit), or strike the sentence and list them as cut. Also:
   - `design/01:222` (Act 7 status) still says "the std-concurrency five
     compile + grade fully". `thread_spawn` and `thread_scope` are
     static-only (HANDOFF known-open 3).
   - Act 1's "Cast Editor highlights the line currently executing / core
     loop" (`design/01:57`) is not built, and no code-status line records it
     as cut.
   - The pitch deck still says 57 missions (owner's file).

8. **CI never runs the slow suites.** Add a `-Full` switch to
   `scripts/ci.ps1`, or a nightly scheduled task on cnc, that runs
   `--ignored` on the pinned toolchain. See the test-posture list below for
   what regresses silently without it.

## v1.1

- **Split the data out of the logic.** `mission.rs` is 3801 lines, and lines
  ~118-2862 are mission literals. Move them to `mission/acts/act_NN.rs` and
  leave about 950 lines of registry, gating and panels. Do the same for
  `editor/solutions/data.rs` (2388) and the `grader.rs` MISSION TABLE.
  `screenshot/scenes.rs` (1592) is capture-only (see below).
  `expectations.rs` (1800, about 600 of it tests) is fine now that `data.rs`
  is split out.
- **The grader duplication is an artefact of a licence rule that does not
  hold.** The "two crates must not share code" rule (`grader.rs:8-12`) is
  stricter than the licences need. An AGPL crate may depend on an MIT crate;
  only the reverse is a problem. Today the GRADER ENGINE and MISSION TABLE
  are copied verbatim between `stub_grader.rs` (MIT) and `grader.rs` (AGPL),
  and the `contract.rs:1778` textual-identity test enforces it. That is sound
  while Matt is the only copyright holder, and it gives the AGPL moat
  nothing, since the same engine is already MIT. It becomes a real licence
  problem the first time an outside contributor patches the AGPL copy: that
  patch cannot be copied into the MIT file without their permission. The
  rule also produces fragile workarounds:
  `compile-api/tests/expectations_proof.rs:103` scrapes `mission.rs` source
  by its 12-space indentation. *Fix:* one MIT `pledge_missions` crate (ids,
  starters, rule table, engine) that both crates depend on. At minimum, add a
  CONTRIBUTING clause requiring contributions to the mirrored regions to be
  dual-licensed.
- **Make the invariants types, not conventions.** `Mission.prereq` and
  `Mission.available` (`mission.rs:31-44`) are written as placeholders in
  every literal and then patched by a loop (`:2867-2892`).
  `MissionRegistry.missions` is a public mutable Vec. Derive both values from
  the index. For a teaching artifact this is the wrong example to set.
- **Stringly-typed ids.** About eight tables key on a static str id. The
  coverage tests mostly hold this together; Should-fix 4 closes the one real
  gap. A `MissionId` newtype is optional.
- **Dead NPC data and index-based placement.** `NPC_ROSTER[*].pos` is dead:
  72 literals that spawning never reads (`npc.rs:611`). Delete the field.
  Placement is keyed by **roster index** (`world::district_slot(i)`), so
  reordering the roster silently moves NPCs between districts. Key it by an
  explicit district field instead.
- **Capture-only code ships in every build.** `screenshot/scenes.rs`, the
  three `EditorSession` scripted-capture hooks (`editor.rs:128-155`),
  `mission::HideNextPinForCapture` (`mission.rs:3259-3280`) and the
  `PNC_SHOTS` reads (`progress.rs:716`, `lib.rs:27`) are all compiled into
  the shipped and wasm binaries. They are env-gated and harmless, but they
  add bundle size and mix test seams into gameplay types. Put them behind a
  `capture` feature. Also: a capture run uses `on_disk()`, so
  `load_or_recover` can rename a corrupt *real* save even in capture mode.
- **`cargo_grader` is public, unsandboxed and unwired.**
  `compile-api/src/cargo_grader.rs` is `pub mod` (`lib.rs:45`). It runs host
  `cargo check` and is used only by tests (`game/tests/contract.rs:24`). Gate
  it with a test/dev cfg or move it to a test helper. `grader.rs:4` claims
  `/compile-real` uses it; it does not.
- `compile-api/src/lib.rs` is 980 lines with all handlers inline. Move them
  to `routes.rs`.
- **The client trusts `ok` over `grade`.** `outcome.rs:157-173`: a reply with
  `ok:true` and `grade:"wrong_output"` becomes `PassedUnverified(Unknown)`
  and a clear. Only clear when `grade` is a pass value.
- **Save durability.** `progress.rs:435` writes the tmp file and renames it
  with no `sync_all`. After a power loss the save can be zero-length; it then
  gets backed up as corrupt and progress is lost.
- `state.rs:137` TODO: tag InGame spawns with `DespawnOnExit` and delete the
  hand-kept sweep list.
- **Logging.** Coverage is good: every plugin logs build, I/O, verdicts and
  refusals. Tokens are redacted (`ApiToken` Debug/Display). Player source is
  logged by length only. Two gaps: native logs go to stdout only, so a player
  has nothing to attach to a bug report (add a rolling file under the save
  dir), and the DEBUG filter is hardcoded in `lib.rs:41-45` (`RUST_LOG`
  still overrides it).
- **Stale docs.**
  - `game/src/lib.rs:4` says "main.rs initialises tracing"; `main.rs:3-7` says the opposite.
  - The `CorePlugin` doc (`plugins/mod.rs:28-30`) still talks about "day-6" subsystems.
  - The `contract.rs:1630` ignore reason says "21 times"; it is 96.
  - HANDOFF known-open 1 says "Three reviews"; there are six.
  - HANDOFF "being fixed in wave 4" (wall-clock tests): check whether still true.
- The three Rust files under `mobile/src-tauri` have no SPDX header.

## Release-blocker sweep (brief item 2): results

- **Strict-linear gating with trials inserted mid-registry, and old saves:**
  safe. No mission id from main was removed or reordered: all 57 old ids
  appear in the same relative order among the 96. A v1 save migrates
  (`progress.rs:342-353`). The inserted stages unlock from their
  already-cleared predecessor, the old frontier still unlocks, and cleared
  missions are always revisitable (`mission.rs:3062`).
  `trial::current_mission` handles the gap.
- **Demo boundary:** correct in code (`mission.rs:2874-2892`). Unavailable
  missions never open, even ones a full save has cleared (`:3038`). The
  epilogue never shows in the demo. Nothing ships the demo (B1), and its
  tests never run under the feature (Should-fix 3).
- **on_disk vs in_memory:** correct. The only `on_disk()` call is
  `CorePlugin` (`plugins/mod.rs:42`), which only `run()` mounts. No test
  mounts either. File tests use temp dirs.
- **Offline, unreachable, and each grade state:** `outcome.rs` maps every
  server grade, 401/413/429/503 and transport errors. Only server passes
  (verified or unverified) persist; fallback stub passes never do; refusals
  don't count as failures. All of this is unit-tested
  (`outcome.rs:524-840`). The problem is the native default target (B2).
- **wasm:** the bindless fix is unconditional (`editor.rs:171-181`). No
  SystemTime, Instant or `std::fs` on a wasm path. Assets are Unprocessed
  with meta check Never. `check-wasm` runs in CI.
- **Panics on main paths:** none found. Every unwrap/expect/panic before
  each file's first `cfg(test)` in `game/src` sits inside a player-program
  string literal. Player-text slicing (`ui_theme/highlight.rs`,
  `editor/diagnostics.rs`) only cuts at ASCII stops or char boundaries, and
  the stub lexer indexes a `Vec<char>`. compile-api non-test code: none.
