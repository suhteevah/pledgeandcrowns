## Hard rule 1

Same as Act 9: `prealloc` and `compiler_alloc` contain `unsafe impl
GlobalAlloc` and `unsafe fn` in the *player's* program and in string data
(starters, solutions, fixtures). Nothing in this act adds `unsafe` to game
or compile-api Rust code. `#[global_allocator]` appears only inside player
programs; the game crate must never declare one.

## Sandbox constraints and what they cost this act

Same sandbox as Act 9: one file, std only, stable, `wasm32-wasip1`,
wasmtime with stdio only, server manifest **edition 2024** (every program
below was verified under both 2021 and 2024; stdout identical). Profiling
tools do not exist there, and wall-clock time is both unavailable to the
grader and nondeterministic, so **no mission grades speed**. Each
performance lesson is expressed as a deterministic, observable quantity:
an allocation count, a borrowed-or-copied flag, a value computed at
compile time.

**Allocation counts.** The expected `allocations: 1` in `prealloc` and
`compiler_alloc` is guaranteed by documented std behaviour, not just
observed: `Vec::with_capacity(n)` allocates once for `n > 0` and non-zero-sized `T`, and `push` never
reallocates while `len < capacity` (Vec docs, "Guarantees"); the same holds
for `String::with_capacity` + `push_str` within capacity. The starter and
wrong-variant counts (9, 8, 12, 2) are *observed* on 1.99.0 and depend on
`Vec`'s growth strategy, which std does not specify; they are recorded to
show the failure, not to be graded. The `collect` and `join` alternatives
measured 1 here but are not contractually 1; the grader accepts them when
they measure 1.

### 67 — `prealloc` (The Assayer)

**NPC.** The Assayer: weighs every coin that enters the Throne's treasury
and trusts no claim she has not measured. "You say it is fast. Put it on
the scale."

**Framing.** The curriculum's Allocation Audit: a ledger that allocates
over and over while it grows.

**Prompt.** "Build the 1000-coin ledger with exactly one allocation."

**Tutorial draft.**

```text
## Concept
Before you optimise, measure. Here the instrument is a counting
allocator: a `#[global_allocator]` that wraps `std::alloc::System` and
bumps an atomic counter on every allocation and reallocation. (Writing
one is `unsafe impl GlobalAlloc`: you promise to honour the allocator
contract, which forwarding to `System` does.) A `Vec` that starts empty
must reallocate as it grows; std does not promise how often. Give it the
final size up front with `Vec::with_capacity(n)` and std does promise:
one allocation, and no reallocation while `len < capacity`. On a real
machine you would reach for `cargo flamegraph`, `perf`, or DHAT, and
crates like `smallvec` to keep small collections off the heap.

## Syntax
let before = ALLOCATIONS.load(Ordering::Relaxed);
let mut v = Vec::with_capacity(1000);
// ... push 1000 times ...
let after = ALLOCATIONS.load(Ordering::Relaxed);

## Task
Change how the ledger is created so building it costs exactly one
allocation. The allocator and the measurement are already written.

## Hint
The scale reads more than 1. Every count above 1 is the Vec outgrowing
its buffer and moving.
```

**Hints.**
1. The scale reads more than 1 (9 on rustc 1.99.0, but std does not promise a number). Every count above 1 is the `Vec` outgrowing its buffer and moving. Player-facing text must not quote the 9.
2. You know the final length before the loop starts: 1000.
3. `let mut ledger = Vec::with_capacity(1000);` (or `(0..1000u32).collect::<Vec<_>>()`, which measures 1 here too).

**Starter** (compiles; wrong output, the intended reason):

```rust
use std::alloc::{GlobalAlloc, Layout, System};
use std::sync::atomic::{AtomicUsize, Ordering};

struct CountingAlloc;

static ALLOCATIONS: AtomicUsize = AtomicUsize::new(0);

unsafe impl GlobalAlloc for CountingAlloc {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        ALLOCATIONS.fetch_add(1, Ordering::Relaxed);
        unsafe { System.alloc(layout) }
    }

    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
        unsafe { System.dealloc(ptr, layout) }
    }

    unsafe fn realloc(&self, ptr: *mut u8, layout: Layout, new_size: usize) -> *mut u8 {
        ALLOCATIONS.fetch_add(1, Ordering::Relaxed);
        unsafe { System.realloc(ptr, layout, new_size) }
    }
}

#[global_allocator]
static GLOBAL: CountingAlloc = CountingAlloc;

fn main() {
    let before = ALLOCATIONS.load(Ordering::Relaxed);

    // The Assayer wants this ledger built with a single allocation.
    let mut ledger = Vec::new();
    for coin in 0..1000u32 {
        ledger.push(coin);
    }

    let after = ALLOCATIONS.load(Ordering::Relaxed);
    println!("coins: {}", ledger.len());
    println!("allocations: {}", after - before);
}
```

```text

allocations: 9
```

**Canonical solution:**

```rust
use std::alloc::{GlobalAlloc, Layout, System};
use std::sync::atomic::{AtomicUsize, Ordering};

/// The assayer's scale: wraps the system allocator and counts every
/// allocation and reallocation. It never prints (printing can allocate).
struct CountingAlloc;

static ALLOCATIONS: AtomicUsize = AtomicUsize::new(0);

// SAFETY: every method forwards to `System`, which upholds the GlobalAlloc
// contract. Bumping an atomic counter does not allocate.
unsafe impl GlobalAlloc for CountingAlloc {
    unsafe fn alloc(&self, layout: Layout) -> *mut u8 {
        ALLOCATIONS.fetch_add(1, Ordering::Relaxed);
        unsafe { System.alloc(layout) }
    }

    unsafe fn dealloc(&self, ptr: *mut u8, layout: Layout) {
        unsafe { System.dealloc(ptr, layout) }
    }

    unsafe fn realloc(&self, ptr: *mut u8, layout: Layout, new_size: usize) -> *mut u8 {
        ALLOCATIONS.fetch_add(1, Ordering::Relaxed);
        unsafe { System.realloc(ptr, layout, new_size) }
    }
}

#[global_allocator]
static GLOBAL: CountingAlloc = CountingAlloc;

fn main() {
    let before = ALLOCATIONS.load(Ordering::Relaxed);

    // Ask for room for every coin up front: one allocation, no regrowth.
    let mut ledger = Vec::with_capacity(1000);
    for coin in 0..1000u32 {
        ledger.push(coin);
    }

    let after = ALLOCATIONS.load(Ordering::Relaxed);
    // Print only after measuring: the first println may allocate a buffer.
    println!("coins: {}", ledger.len());
    println!("allocations: {}", after - before);
}
```

**Expected stdout:**

```text
coins: 1000
allocations: 1
```

**Why this is sound.** Every `GlobalAlloc` method forwards its arguments
unchanged to `System`, which upholds the trait's contract (alignment,
layout matching between `alloc` and `dealloc`/`realloc`); `alloc_zeroed`
uses the trait default, which calls our `alloc`. The counter is a static
`AtomicUsize`; `fetch_add` does not allocate, so the allocator cannot
recurse. Nothing prints inside the allocator (the first `println!` can
allocate stdout's buffer), and the measurement window closes before the
first `println!`.

### 68 — `cow_borrow` (The Copyist)

**NPC.** The Copyist: an old scribe who refuses to recopy a page that is
already correct. "Copy only what must change."

**Framing.** Shelf names need underscores instead of spaces. Most titles
have none.

**Prompt.** "Return `Cow<'_, str>`: borrow titles that need no change, copy only the rest."

**Tutorial draft.**

```text
## Concept
`Cow<'a, str>` ("clone on write") is either `Cow::Borrowed(&'a str)` or
`Cow::Owned(String)`. It dereferences to `&str`, so callers use it like
any string. A function that only sometimes changes its input can return
the input itself, borrowed, when nothing changes, and build a new
`String` only when something does. The common case then allocates
nothing. Call `.into_owned()` if you later need a `String`; it copies
only if the value was borrowed.

## Syntax
fn tidy(s: &str) -> Cow<'_, str> {
    if needs_change(s) { Cow::Owned(fix(s)) } else { Cow::Borrowed(s) }
}

## Task
Make `shelf_name` return `Cow<'_, str>`, borrowing titles without spaces,
and print each name with `(borrowed)` or `(copied)`.

## Hint
`replace` always builds a new String, even when there is nothing to
replace.
```

**Hints.**
1. `replace` always builds a new `String`, even when there is nothing to replace.
2. `if title.contains(' ') { Cow::Owned(title.replace(' ', "_")) } else { Cow::Borrowed(title) }`, return type `Cow<'_, str>`.
3. In `main`, `match &name { Cow::Borrowed(_) => "borrowed", Cow::Owned(_) => "copied" }`.

**Starter** (compiles; wrong output):

```rust
/// Shelf names use underscores instead of spaces. This version builds a
/// brand-new String for every title, even ones with nothing to change.
fn shelf_name(title: &str) -> String {
    title.replace(' ', "_")
}

fn main() {
    for title in ["Grimoire", "Book of Crowns", "Ledger"] {
        let name = shelf_name(title);
        // The Copyist wants each line to end with (borrowed) or (copied).
        println!("{name}");
    }
}
```

```text
Grimoire
Book_of_Crowns
Ledger
```

**Canonical solution:**

```rust
use std::borrow::Cow;

/// Shelf names use underscores instead of spaces. Most titles have no
/// spaces, so borrow those as-is and only copy when something must change.
fn shelf_name(title: &str) -> Cow<'_, str> {
    if title.contains(' ') {
        Cow::Owned(title.replace(' ', "_"))
    } else {
        Cow::Borrowed(title)
    }
}

fn main() {
    for title in ["Grimoire", "Book of Crowns", "Ledger"] {
        let name = shelf_name(title);
        let how = match &name {
            Cow::Borrowed(_) => "borrowed",
            Cow::Owned(_) => "copied",
        };
        println!("{name} ({how})");
    }
}
```

**Expected stdout:**

```text
Grimoire (borrowed)
Book_of_Crowns (copied)
Ledger (borrowed)
```

### 69 — `const_eval` (The Astronomer)

**NPC.** The Astronomer: draws every star chart before nightfall so that
nothing need be calculated in the dark. "The sky does not change. Why
compute it twice?"

**Framing.** The fastest work is work done before the program runs.

**Prompt.** "Make `star_table` a `const fn`, compute `STARS` at compile time, and check it with a compile-time `assert!`."

**Tutorial draft.**

```text
## Concept
A `const` item's value is computed by the compiler and baked into the
program; no run-time work builds it. Only `const fn`s may be called
there. A `const fn` is an ordinary function that can also run inside the
compiler, so its body is limited: no heap allocation, no `for` loops
(they call `Iterator::next`, which is not const), but `while`, `if`,
`match`, arithmetic and array indexing are fine. `const _: () =
assert!(cond, "msg");` makes the build fail if `cond` is false: a test
that runs at compile time. (`#[inline]` is the other compile-time hint
you will meet; its effect cannot be seen from a program's output.)

## Syntax
const fn square(n: u32) -> u32 { n * n }
const NINE: u32 = square(3);
const _: () = assert!(NINE == 9, "bad square");

## Task
Make `star_table` a `const fn` so `STARS` is computed at compile time,
and add a compile-time check that the last star is 50.

## Hint
E0015: a `const` can only call `const fn`s.
```

**Hints.**
1. E0015: a `const` can only call `const fn`s.
2. Adding `const` alone is not enough: the `for` loop gives another E0015, "cannot use `for` loop on `std::ops::Range<usize>` in constant functions" (verified on 1.99.0). Use `let mut i = 0; while i < 8 { ...; i += 1; }`.
3. Add `const _: () = assert!(STARS[7] == 50, "the last star is misplaced");` at the top level.

**Starter** (fails: E0015, the intended reason):

```rust
fn star_table() -> [u32; 8] {
    let mut table = [0u32; 8];
    for i in 0..8 {
        table[i] = (i as u32) * (i as u32) + 1;
    }
    table
}

// The Astronomer wants the chart drawn before the night begins: computed
// by the compiler, and checked by it too.
const STARS: [u32; 8] = star_table();

fn main() {
    println!("star chart: {STARS:?}");
    println!("brightest: {}", STARS[7]);
}
```

**Canonical solution:**

```rust
/// A `const fn` can run inside the compiler when it is used to compute a
/// constant. `for` loops are not allowed in const fns (they call
/// `Iterator::next`, which is not const), so this uses `while`.
const fn star_table() -> [u32; 8] {
    let mut table = [0u32; 8];
    let mut i = 0;
    while i < 8 {
        table[i] = (i as u32) * (i as u32) + 1;
        i += 1;
    }
    table
}

/// Computed once, during compilation. The finished array is baked into
/// the program; no work happens at run time to build it.
const STARS: [u32; 8] = star_table();

// Checked during compilation: if this were false, the program would not
// build at all.
const _: () = assert!(STARS[7] == 50, "the last star is misplaced");

fn main() {
    println!("star chart: {STARS:?}");
    println!("brightest: {}", STARS[7]);
}
```

**Expected stdout:**


### 70 — `chunks_exact` (The Choirmaster)

**NPC.** The Choirmaster: conducts four voices that sing in parallel and
will not let a soloist go unheard. "Four lanes, one breath. Then the
soloists."

**Framing.** The curriculum's SIMD Shrine, without the SIMD: the shape of
code that SIMD hardware is built for.

**Prompt.** "Sum in four lanes with `chunks_exact(4)` and don't drop the remainder."

**Tutorial draft.**

```text
## Concept
SIMD hardware adds several numbers in one instruction, in parallel
"lanes". Code that suits it works in fixed-width chunks with independent
accumulators, so no step waits on the one before. `chunks_exact(4)`
yields only full 4-element slices; because every chunk has exactly 4
elements, the compiler can drop bounds checks and may vectorise the lane
loop. The 0 to 3 elements left over are not yielded: they wait in
`.remainder()`, and forgetting them is the classic bug. Portable SIMD
(`std::simd`) is nightly-only, and this sandbox cannot time code or
enable wasm SIMD, so the Choirmaster checks the answer, not the speed.

## Syntax

for chunk in &mut chunks { /* 4 elements */ }
let rest = chunks.remainder();   // 0..=3 elements

## Task
Fix `choir_sum` so it adds the voices that do not fill a whole chunk.

## Hint
1 + 2 + ... + 10 is 55. The choir sings 36: voices 9 and 10 are never
heard.
```

**Hints.**

### 71 — `no_std` (The Hermit)

supply line, no market and no heap. "What I cannot carry, I do without."

**Framing.** The curriculum's `no_std` Outpost: port a function to a place


### 72 — `semver_caret` (The Registrar)

**NPC.** The Registrar: keeps the great register of every crate in the
realm and every version it was ever published at. "A version number is a
promise about the next one."

**Framing.** The ecosystem lesson: what `serde = "1.2"` in a
`Cargo.toml` actually allows Cargo to pick.

**Prompt.** "Fix `caret_allows` so it follows Cargo's caret rule below 1.0 too."

**Tutorial draft.**

```text
## Concept
In Cargo.toml, `serde = "1.2.3"` means the caret requirement `^1.2.3`:
any version >= 1.2.3 and < 2.0.0. Cargo assumes semver: a change to the
leftmost non-zero part may break you, anything to its right should not.
Below 1.0 that moves right: `^0.2.3` allows >= 0.2.3, < 0.3.0, and
`^0.0.3` allows only 0.0.3. `Cargo.lock` records the exact versions
chosen; `cargo update` picks newer ones the requirements allow. The rest
of the ecosystem: `rustup` installs toolchains, `cargo fmt` (rustfmt)
formats, `cargo clippy` lints, `cargo doc` builds docs and docs.rs hosts
them for every crate on crates.io. None of those run in this sandbox; the
caret rule does.

## Task
Make `caret_allows(required, candidate)` follow the caret rule for 1.x,
0.x and 0.0.x requirements. (Pre-release tags are out of scope.)

## Hint
The rule is right for 1.2.3 and wrong for 0.2.3: it lets 0.3.0 through.
```

**Hints.**
1. The rule is right for `^1.2.3` and wrong for `^0.2.3`: it lets 0.3.0 through.
2. Find the leftmost non-zero part of `required`; the candidate must match `required` up to and including it.
3. `if required.major > 0 { same major } else if required.minor > 0 { major 0 and same minor } else { major 0, minor 0 and same patch }`, after rejecting `candidate < required`.

### 73 — `compiler_alloc` (trial 1/3): the proclamation

**Concept.** Capstone of Act 10's allocation lessons: build a string with

**Prompt.** "Build the court's proclamation with exactly one allocation."

**Tutorial draft.**

### 74 — `compiler_lifetime` (trial 2/3): the herald

**Concept.** Lifetime elision fails with two reference inputs; name the
lifetime, and tie the result only to the input it can actually borrow
from. Combines Act 2/4 lifetimes with Act 10's `Cow`.

**Prompt.** "Give `herald` a lifetime that ties the result only to `name`."

### 75 — `compiler_bound` (trial 3/3): the last proof

## Open questions for Matt

1. **Performance without timing.** Every Act 10 lesson is graded on a
   deterministic quantity (allocation count, borrowed/copied, compile-time
   value), never on speed. The curriculum's "observe the speedup" moments
   become tutorial text. Acceptable?
2. **SIMD.** `std::simd` is nightly-only and wasm SIMD is not enabled on
   the server. `chunks_exact` teaches the shape and says the speed-up
   cannot be shown. Alternatively, enable `simd128` for player builds
   (server-owned flag, no player input) and add a `core::arch::wasm32`
   mission — that requires `unsafe` intrinsics and a server change. Keep
   the substitute?
3. **Credits.** Reuse the existing epilogue panel as the credits, or build
   a dedicated credits scene (and the optional "your 75 programs" view)?
4. **Ecosystem coverage.** Only the caret rule is graded; cargo, rustup,
   clippy, rustfmt, docs.rs and crates.io are tutorial text. Is that
   enough to meet the curriculum's acceptance line ("can navigate cargo,
   clippy, rustfmt, docs.rs ... unaided")?
5. **Compiler messages and toolchain drift.** The Compiler's words are
   only correct for the toolchain that produced them. Pin the server's
   toolchain version (and record it in this spec) so a rustup update does
   not silently change what the boss "says"?
6. **The watching cast.** Placing earlier bosses around the Throne plaza
   once their acts are cleared is cosmetic and cheap. In or out for v1.0?
